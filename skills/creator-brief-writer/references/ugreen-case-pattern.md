# UGREEN 案例提炼

## 案例范围

两份案例都是 UGREEN NAS 面向摄影内容创作者的产品视频 Brief：

- DXP4800 Plus：平台包含 YouTube、TikTok、Instagram，强调高容量、AI 相册、传输速度和远程协作。
- DH4300 Plus：平台以 YouTube 为主，强调一体化存储、易安装、多用户权限、传输同步和数据安全。

这里提炼的是写法和结构，不把案例中的型号、价格、容量、折扣、日期或链接当作新项目默认事实。

## 共通结构

### 1. 项目元信息

先把“谁、推什么、在哪发、什么时候发、去哪转化”写清楚：

- 产品 / SKU
- Promotion link 和 CTA
- 公开时间窗口
- 平台
- 联系人 / 审核状态（案例里未完整提供时标记待补）

### 2. 一句话定位

先给产品一个创作者能复述的角色，例如“行业改变者”或“一体化存储方案”。定位要服务后面的内容，不要只写产品名。

### 3. Talking Points

案例的每个卖点通常包含四层：

1. 用户问题：云存储贵、容量有限、隐私担忧、传输慢、协作低效；
2. 产品能力：本地存储、容量、AI 分类、网络与处理性能、权限、跨设备访问；
3. 事实证明：容量、速度、兼容格式、支持平台等；
4. 拍摄建议：成本对比、上传实测、屏幕录制、远程协作、权限设置、兼容列表。

因此，不要只写“突出 AI 功能”，要写成“展示什么操作、观众看见什么结果”。

### 4. 强制要求

案例中真正影响交付的硬要求包括：

- 产品包装或画面必须出现品牌名；
- 标题必须包含指定品牌 / 产品关键词；
- 发布前先提交 concept 或 script；
- 发布前至少预留指定审核缓冲；
- 品牌拥有在自有网络发布、编辑或再利用内容的权限（需明确范围和期限）；
- 描述首行放链接并加入折扣 CTA；
- 指定场景必须实拍或录屏；
- 指定 hashtag / tag。

这些要从“内容建议”单独拎出，形成验收清单。

### 5. 场景写法

把场景写成可执行动作：

| 场景 | 不够可执行 | 可执行写法 |
|---|---|---|
| 存储 | 展示大容量 | 上传一段明确大小的视频，同时展示上传路径、耗时和对比方案 |
| AI 相册 | 展示 AI 功能 | 录屏展示人物 / 地点分类，并展示相似照片筛选过程 |
| 协作 | 展示多人共享 | 一人远程上传，另一人用授权账号打开并编辑文件 |
| 多端访问 | 支持多设备 | 用手机或电脑远程打开同一文件，并说明使用入口 |
| 安全 | 强调安全 | 展示安全管理界面、权限设置或本地存储路径，并避免超出证据的绝对承诺 |

### 6. 两份案例体现出的可变字段

不同 SKU 的 Brief 不应只替换产品名，还要同步调整：

- 平台组合与内容时长；
- 产品定位；
- 容量 / 速度等证明数字；
- 必拍场景的数量和复杂度；
- 适合的创作者类型；
- 是否突出易安装、权限、安全或协作；
- 审核节奏与交付要求。

## 结构化判断

写 Brief 时，把信息分成四类：

1. **硬要求**：不满足就不能发布或无法验收；
2. **核心信息**：创作者必须理解并讲对；
3. **创意建议**：帮助创作者完成表达，但允许发挥；
4. **待验证 / 待补**：链接、折扣、日期、性能、权利范围、审稿人等。

## 常见缺口

从案例结构看，实际新 Brief 最容易缺少：

- 具体受众和购买场景；
- 核心 KPI 及归因方式；
- 口播禁用词和合规要求；
- 样品 / 硬盘 / 账号 / 测试素材准备人；
- 具体审核人和回复 SLA；
- 修改轮次、逾期处理；
- 有机发布与付费投放的使用权范围；
- 失败时的替代拍摄方案。
